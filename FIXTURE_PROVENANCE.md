# Public fixture provenance

The `src/**/*.golden.json` files preserve contracts captured during the migration from
the historical Burrow CLI and Mole-based digger. They are expected inputs to tests,
not output generated by the Rust implementation under test.

Before the initial public snapshot on 2026-09-06, these copies were anonymized. No
private capture or replacement map is included in this repository. The filenames
remain stable so existing contract tests continue to load their expected inputs.

## What changed

- Home and workspace prefixes use a fictional user. Opaque cache UUIDs, account-like
  numeric identifiers and long cache hashes use deterministic placeholders. Malformed
  log paths retain their embedded JSON and control characters with fictional app names.
- Status and network captures use fictional host, process, device and network
  identities. Live usage counters were replaced with internally consistent example
  values. Network addresses use the documentation range `192.0.2.0/24`; Bluetooth
  addresses use the locally administered `02:00:00:00:00:xx` range. IPv6 link-local
  parser examples use synthetic suffixes.
- The seven uninstall rows describe fictional applications. Nested paths, the
  three plain-App/four Homebrew split, and display-name/cask-token relationships
  remain represented. These rows are example bundle inputs, not an inventory.
- The duplicate report retains its controlled temporary-file groups, sizes and
  hashes; its working directory, command path and capture time are anonymous.
- Embedded Bluetooth, display and network parser captures use the same anonymized
  identities as the JSON fixtures. Parser quirks such as dotted process names,
  `.exe` suffixes, spaces, connected-section ordering and missing fields remain.

All JSON object keys, nesting, array lengths, primitive kinds, nulls and booleans
were preserved. Every captured clean protection/whitelist/deletion verdict and
aggregate count is unchanged. Timestamp examples retain fractional seconds and a
numeric UTC offset because those formats are part of the decoder contract.

The large protection corpora also contain public application identifiers and system
paths that are literal inputs to the deletion policy, including synthetic near-miss
variants. They do not assert that those applications are installed. Removing or
renaming policy identifiers would destroy the safety cases these corpora exercise.

## Duplicate apply capture recipe

The independent apply capture was recorded on 2026-08-08 with the historical shipping
CLI (version 0.0.1) and fclones 0.35.0. Its fixture was rebuilt before **each** of
`dupes remove <fixture> --apply`, `dupes link <fixture> --apply`, and
`dupes dedupe <fixture> --apply`. A second action on an already consumed fixture is
not equivalent: it can return the structured zero-group skip response.

The controlled fixture contained `a/one.bin` and `b/one_copy.bin` with identical
9,600-byte content `bytes((i * 7 + 11) % 251 for i in range(9600))`;
`a/two.bin` and `b/two_copy.bin` shared 7,200 bytes
`bytes((i * 13 + 29) % 241 for i in range(7200))`. The unique `a/uniq.bin`
contained `bytes((i * 3 + 5) % 233 for i in range(4096))`. Each capture used a newly
created temporary directory; no user files were inputs. Discovery found two groups,
four grouped files, 33,600 grouped bytes and 16,800 redundant bytes.

All three actions emitted empty stdout from fclones, whose progress report went to
stderr. The historical CLI wrapped that empty stdout as `data: {"text": ""}`;
this is the apply fixture's contract. Envelope version and engine labels differ in
the Rust port and are not pinned to that historical CLI. This recipe and behavior
come from the original capture's provenance and fixture builder, not from output of
the Rust implementation under test. Public path aliases remain described above.

## Verification and future updates

`python3 scripts/check_fixtures.py` verifies the public fixture inventory, hashes,
captured safety totals, timestamp formats and selected accounting relationships.
`cargo test` runs the behavioral and serializer tests against these public inputs.
The private migration tree's byte-for-byte copy check intentionally does not apply
to these anonymized copies.

Any future recapture must use controlled temporary data and the independent
reference implementation. Review the structural and behavioral diff before changing
`fixtures-manifest.json`; do not copy output from the code being tested into its
expected fixture. Keep personal captures, process dumps and replacement maps out of
Git history.
